# Phase 2 Acceptance Criteria

## 目的
Phase 3 の実装完了判定と Phase 4 の QA 観点を揃えるため、MVP の受入基準を Must 機能中心に定義する。

## 対象範囲
- 画像アップロード
- 3D プレビュー表示
- LED 色変更
- 明るさ変更
- 背景切替
- カメラ操作
- 保存
- エラー時挙動

## 受入基準

### 1. 画像アップロード
- PNG 画像を選択すると、短時間でプレビューへ反映される
- PNG 以外を選択した場合、ユーザーが再選択できるエラーメッセージが表示される
- 読み込み失敗時も画面全体が壊れない

### 2. プレビュー表示
- アクリルスタンド風の 3D 表示が崩れずに表示される
- 画像未選択時はプレースホルダーまたは案内表示になる
- 一般的なデスクトップブラウザで主要レイアウトが崩れない

### 3. 発光設定
- LED 色プリセットを切り替えると見た目が変化する
- 明るさスライダー操作がプレビューへ反映される
- 発光設定の変更で他の設定値が失われない

### 4. 表示設定
- 背景プリセットの切替が即時反映される
- カメラプリセット切替またはリセットが機能する
- 表示設定の変更中に操作パネルが利用不能にならない

### 5. 保存
- 現在のプレビューを画像として保存できる
- 保存成功時に成功状態が明確に表示される
- 保存結果画面または保存完了モーダルから次の操作へ進める

### 6. エラー時挙動
- 保存失敗時に現在の画像と設定が保持される
- エラーメッセージが次の行動を示している
- 保存失敗で画面遷移しない

## 非機能基準

### パフォーマンス
- 画像アップロード後のプレビュー表示が体感で大きく待たされない
- カメラや設定変更時に極端な遅延がない

### 対応環境
- Chrome 最新版
- Edge 最新版
- Safari 最新版
- デスクトップ優先

## 除外事項
- 光学的に厳密な再現
- 共有 URL
- 保存履歴一覧
- 注文導線
- 本格的なアカウント管理

## QA チェック観点

| 観点 | 確認内容 |
|---|---|
| 基本導線 | トップ画面から保存完了まで迷わず進める |
| 入力制約 | 非 PNG や壊れた画像で異常終了しない |
| 見た目 | 主要 UI と 3D 表示が重ならず読める |
| 保存 | 書き出し成功 / 失敗時の通知が適切 |
| 回復性 | エラー後に再試行できる |
