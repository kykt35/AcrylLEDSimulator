# MVP User Flow

## 目的

初回訪問から画像のダウンロードまでを1画面で完結させる現行MVPの導線と、失敗・復元・初期化の分岐を定義する。

## 入口

| URL | 役割 |
|---|---|
| `/` | `SimulatorScreen` を表示する |
| `/simulator` | `/` と同じ `SimulatorScreen` を表示する |
| `/usage` | 使い方を表示し、`/` へ戻る導線を提供する |
| `/about` | アプリ概要を表示し、`/` で試す導線を提供する |

`/` と `/simulator` の機能差はない。画像入力、調整、書き出しはどちらのURLでも同じ画面内で行う。

## 主導線

```text
/ または /simulator
  ↓ PNGをドラッグ&ドロップ、またはプレビューをクリックして選択
3Dプレビューと彫刻用画像を生成
  ↓ ライト / カメラ / 配置 / 彫刻を調整
書出し形式と範囲を確認
  ↓ 「画像をダウンロードする」
CanvasをPNG/JPGのBlobへ変換
  ↓
編集スナップショットをsessionStorageへ保存
  ↓
ブラウザのローカルダウンロードを開始
  ↓
成功toastを表示
  ↓
同じ画面と設定のまま編集を継続
```

この導線では結果画面へ遷移せず、サーバーへの画像アップロードやシミュレーション保存も行わない。

## ユースケース別フロー

### 1. 初回訪問からシミュレーション画像をダウンロードする

1. ユーザーが `/` または `/simulator` へ到達する
2. 空の3DビューへPNGをドラッグするか、クリックしてファイルを選択する
3. 画像読込と彫刻用画像生成の完了を待つ
4. ライト、カメラ、配置、彫刻の各タブで見え方を調整する
5. 必要に応じて書出範囲を移動またはリサイズする
6. 書出しタブでPNGまたはJPGを選び、ダウンロードを実行する
7. 成功toastを確認し、そのまま調整または再ダウンロードを続ける

### 2. 画像を差し替える

1. 画像読込済みの3Dビューへ別のPNGをドロップする
2. 新しい画像の読込と彫刻用画像生成が完了する
3. 書出範囲は全面へ戻り、書出範囲オーバーレイは閉じる
4. 画像配置や彫刻設定を必要に応じて調整する

### 3. ダウンロード失敗から復帰する

1. ユーザーがシミュレーション画像のダウンロードを実行する
2. Canvas取得やBlob生成に失敗する
3. 画面内にエラーメッセージを表示する
4. 現在の画像と設定を保持したまま、設定変更または再試行を行う
5. 成功時はローカルダウンロードを開始し、成功toastを表示する

### 4. 保存済み編集状態を復元または初期化する

- `?resume=1` で開いた場合、利用可能な編集スナップショットを復元する
- スナップショットがない場合は初期状態を表示する
- `?reset=1` で開くか画面上のリセットを実行した場合、画面状態と保存済みスナップショットを初期化する

## 主要分岐

### 分岐 A: PNG読込前

- PNG追加を促す空状態を表示する
- 設定タブとダウンロード操作は表示しない
- プレビュー面はクリック、Enter、Spaceでファイル選択を開ける

### 分岐 B: PNG読込失敗

- PNG以外、8MB超過、読込失敗をメッセージで通知する
- 有効な画像がない場合は空状態へ戻り、再選択できる
- サーバーAPIへのフォールバックは行わない

### 分岐 C: 調整中

- ライト、背景、カメラ、配置、彫刻の変更をプレビューへ反映する
- 設定パネルはタブ押下で開閉し、Escapeまたは3Dビュー押下で閉じる
- 書出範囲オーバーレイ表示中はプレビューのカメラ操作を抑止する

### 分岐 D: ダウンロード成功

- Blob生成後に編集スナップショットを保存し、ブラウザのダウンロードを開始する
- 成功toastで形式と開始済みであることを伝える
- toastは閉じる操作を提供し、編集状態やURLは変更しない

### 分岐 E: ダウンロード失敗

- 現在のプレビューと設定を失わない
- 再試行可能なエラーメッセージを画面内に表示する
- 結果画面への遷移やサーバー保存の再試行は行わない

## データ境界

| 区間 | 受け渡し内容 |
|---|---|
| ファイル選択 → 画面状態 | PNGをFileReaderでData URLへ変換し、元画像と彫刻画像を保持する |
| 画面状態 → 3Dプレビュー | 画像、彫刻モード、ライト、背景、カメラ、配置、アクリルサイズをpropsで渡す |
| 3Dプレビュー → ダウンロード | Canvasとクロップ範囲から一時Blobを生成する |
| ダウンロード時 → sessionStorage | 元画像、彫刻画像、調整値、表示設定を `EditorSnapshot` として保存する |
| ブラウザ → ローカルファイル | Object URLを使う一時リンクからPNG/JPGをダウンロードする |

## UXルール

- 主導線は「PNGを追加 → 見え方を調整 → ダウンロード」に統一する
- ユーザー向け文言では、ローカル出力を「ダウンロード」と表現する
- 処理中は対象操作の二重実行を防ぎ、状態をライブリージョンでも通知する
- エラー時は現在の編集内容を可能な限り保持する
- ダウンロード成功後も同じ画面で比較、調整、再ダウンロードできる

## 将来候補

以下は現行MVPに含めない。

- 保存結果専用画面
- サーバーへの画像・シミュレーション永続化
- 共有URL
- 保存履歴、比較保存
- 注文フロー

追加する場合は、現行のローカルダウンロードと区別し、API契約、認証、ストレージ、保持期間、エラー処理を別途設計する。
