# 仕様ドキュメント

このディレクトリは、Acryl LED Simulator の仕様を管理する正の置き場所です。`.docs/` は計画、調査、実装チェックリストなどの作業管理用として扱います。

## 参照順序

1. `feature-index.md` で対象機能と詳細仕様を確認する
2. `product/` で目的、スコープ、受け入れ条件を確認する
3. `ux/` で画面、ユーザーフロー、UI方針を確認する
4. `architecture/` で状態、データ、API、エラー、技術構成を確認する
5. `features/` で実装変更対象の振る舞い、例外、関連実装、関連テストを確認する
6. `operations/spec-maintenance.md` で仕様更新が必要か判断する

## ディレクトリ責務

| ディレクトリ | 責務 |
|---|---|
| `product/` | プロダクト要件、開発計画、受け入れ条件 |
| `ux/` | ユーザーフロー、画面仕様、UIデザイン |
| `architecture/` | 技術構成、コンポーネント、状態、データ、API、エラー処理 |
| `features/` | 機能別の詳細仕様、エラー、関連実装、関連テスト |
| `operations/` | 仕様更新ルール、変更履歴、リリース受入記録 |

## 仕様追加ルール

- 新しい機能を追加する場合は、`feature-index.md` に行を追加し、必要に応じて `features/*.md` を作成する。
- 既存機能の振る舞い、状態、エラー、保存データ、書き出し結果が変わる場合は、該当する `features/*.md` を更新する。
- 実装から断定できない内容は、詳細仕様の `未確認・推定` に残す。
- `feature-index.md` は一覧とリンクだけにし、具体的な振る舞いは詳細仕様へ書く。
- 既存仕様を移動する場合は、旧パスとの二重管理を避ける。

## 命名規約

- ファイル名は英小文字のkebab-caseを使う。
- 入口文書は `README.md` と `feature-index.md` に限定する。
- 詳細仕様は1ファイル1領域を基本にし、複数機能をまとめる場合は関連が強い範囲に限る。
