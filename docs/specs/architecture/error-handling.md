# Error Handling

## 目的

画像入力、彫刻生成、3D表示、書き出し、セッション保存で発生する失敗と、現行MVPの画面応答を定義する。

## 基本方針

- エラー時も現在のプレビューと設定を可能な限り保持する
- ユーザーへ失敗した操作と次に取れる行動を伝える
- 重大でない失敗は画面内の `ErrorNotice` で表示する
- エラーだけを理由に画面遷移またはサーバー送信を行わない
- セッション保存だけが失敗した場合はメモリへフォールバックし、ダウンロードを継続する

## エラーパターン一覧

| 区分 | 代表原因 | UI応答 |
|---|---|---|
| image input | PNG以外 | PNGを再選択するよう案内 |
| image input | 8MB超過 | 8MB以下のPNGを選ぶよう案内 |
| image input | FileReader失敗 | 画像読込エラーを表示し再選択可能にする |
| engraving | Canvas/Image初期化または画像処理失敗 | 彫刻生成エラーを表示 |
| preview composition | 配置済み画像の合成失敗 | 元Data URLへフォールバック |
| WebGL | 初期化失敗またはcontext lost | フォールバックと再読み込みを表示 |
| export preview | Canvas未取得またはData URL生成失敗 | 書出しプレビューを表示しない |
| download | プレビュー/Canvas未取得、Canvas初期化、Blob生成失敗 | ダウンロードエラーを表示し設定を保持 |
| session | sessionStorage利用不可、quota超過 | メモリ保存へフォールバック |
| session | JSON不正 | メモリ値を使い、なければ復元しない |

現行MVPに `INVALID_PAYLOAD`、`INVALID_SIMULATION`、`SAVE_FAILED` などのサーバーエラーコードは存在しない。

## 画像入力

### PNG以外

- 発生条件: `file.type !== "image/png"`
- メッセージ: `PNGファイルを選択してください。`
- 画像未選択の場合は空状態を維持し、再選択できる

### サイズ上限超過

- 発生条件: 8MBを超えるPNG
- メッセージ: `8MB 以下の PNG ファイルを選択してください。`
- サーバーアップロードへ切り替えず、別ファイルの選択を待つ

### FileReaderまたは初期画像処理失敗

- `loadPngTexture` が返した例外メッセージを画像読込エラーとして表示する
- 新規読込に失敗した場合、設定タブとダウンロード操作は表示しない
- 再度クリック、Enter、Space、ドラッグ&ドロップで選択できる

## 彫刻生成と配置合成

- 彫刻生成失敗は `engraving.status = "error"` とし、`ErrorNotice` を表示する
- 配置済み元画像または彫刻画像の合成失敗は、元Data URLへフォールバックする
- 非同期処理のcleanup後に完了した結果はstateへ反映しない

## 3D表示

- WebGL初期化失敗またはcontext lost時はCanvasを隠し、フォールバックを表示する
- 再読み込み操作でCanvasを再生成する
- WebGL失敗は画像stateやシミュレーション設定を初期化しない

## 書出しプレビュー

- 対象Canvasがない場合は `null` を返し、書出しプレビューを表示しない
- Canvasクロップまたは `toDataURL` の例外も `null` として扱う
- 書出しプレビューの失敗だけではダウンロードstateをerrorにしない

## シミュレーション画像のダウンロード

| 条件 | メッセージ |
|---|---|
| プレビュー領域がない | `プレビュー領域が見つかりません。` |
| 対象Canvasがない | `書き出し対象の canvas が見つかりません。` |
| クロップ用Canvasの2D contextがない | `書き出し用の canvas を初期化できません。` |
| `toBlob` がBlobを返さない | `画像の書き出しに失敗しました。` |
| Error以外の例外 | `ダウンロードに失敗しました。時間をおいて再試行してください。` |

- 開始時に `save.status = "saving"` として二重実行を防ぐ
- 失敗時は `save.status = "error"` とし、メッセージを `ErrorNotice` へ表示する
- 元画像、彫刻画像、シミュレーション設定、書出範囲を保持する
- 画面遷移せず、設定変更または再試行を可能にする

## 彫刻用PNGのダウンロード

- 彫刻Data URLがない場合は処理を開始しない
- 不正なData URLは `彫刻用画像の形式が不正です。` としてrejectする
- 呼び出し側に専用のerror stateはなく、シミュレーション画像のダウンロードとは別処理として扱う

## セッション保存・復元

- sessionStorage書き込み例外は外へ投げず、直前に保持したメモリスナップショットを利用する
- sessionStorageのJSON解析に失敗した場合はメモリスナップショットへフォールバックする
- sessionStorageに値がなくメモリにもない場合は `null` を返す
- `?resume=1` で `null` の場合は初期画面を維持する

## エラー表示ルール

- 画像読込、彫刻生成、ダウンロードはそれぞれ別のタイトルで表示する
- 同じ失敗をtoastとエラーの両方へ重複表示しない
- 成功toastはerror stateでは表示しない
- エラー表示中でも安全な設定変更と再試行を許可する
- 処理状態は視覚表示とライブリージョンで通知する

## 監視とログ

- 現行MVPにサーバー監視、永続ログ、利用者単位のエラー追跡はない
- 将来サーバーAPIを導入する場合に、エラーコード、リクエスト識別子、ログ、メトリクスを同時に設計する

## QA観点

- 非PNG、8MB超過、FileReader失敗から再選択できる
- 彫刻生成失敗後も元画像の状態を確認できる
- WebGL context lostからCanvasを再生成できる
- Canvas書き出し失敗後も画像と設定を保持し、再試行できる
- sessionStorage利用不可またはJSON不正で画面が異常終了しない
- APIや結果画面を前提とするエラー処理が現行MVPへ混在していない
