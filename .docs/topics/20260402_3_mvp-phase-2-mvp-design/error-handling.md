# Phase 2 Error Handling

## 目的
画像読み込み、プレビュー維持、保存処理で発生する失敗パターンと UI 応答を定義し、実装と QA の判断を揃える。

## 基本方針
- エラー時も可能な限り現在のプレビュー状態を保持する
- ユーザーに再試行可能かどうかを明確に伝える
- 技術的な原因ではなく、次に取るべき行動を優先して表示する

## エラーパターン一覧

| 区分 | コード | 代表原因 | UI 応答 |
|---|---|---|---|
| upload | `INVALID_FILE` | PNG 以外を選択 | PNG のみ対応と表示し再選択を促す |
| upload | `FILE_TOO_LARGE` | サイズ上限超過 | 制限値を案内し再選択を促す |
| upload | `UPLOAD_FAILED` | 画像読み込みや保存先失敗 | 再試行導線を表示する |
| export | `EXPORT_FAILED` | Canvas 書き出し失敗 | 設定保持のまま再保存導線を出す |
| save | `INVALID_PAYLOAD` | 不正データ送信 | 状態初期化せずエラー表示する |
| save | `SAVE_FAILED` | サーバー保存失敗 | 後で再試行可能と案内する |

## 画像アップロード時

### 非 PNG ファイル
- 発生条件: `accept="image/png"` を回避して不正ファイルが選択された場合
- UI 応答:
  - エラーメッセージ表示
  - 直前の有効画像がある場合はそのまま維持
  - 保存ボタンは現在の有効状態に応じて維持

### 読み込み失敗
- 発生条件: 壊れた PNG、ブラウザ読み込み失敗
- UI 応答:
  - 読み込み失敗メッセージ
  - 再試行導線
  - 新規未設定状態または直前画像の維持

## 保存時

### 書き出し失敗
- 発生条件: Canvas 未取得、Data URL 生成失敗
- UI 応答:
  - `画像書き出しに失敗しました。再試行してください。`
  - 保存ボタンを再度押せる状態に戻す
  - 画面遷移しない

### API 保存失敗
- 発生条件: `/api/save` が `500` またはネットワーク失敗
- UI 応答:
  - `保存に失敗しました。時間をおいて再試行してください。`
  - 現在の設定とプレビューは保持する
  - 結果画面へ遷移しない

## エラー表示ルール
- 文言は短く、次の行動を含める
- 同一エラーを複数箇所へ重複表示しない
- 重大でないエラーはモーダルではなく画面内通知で扱う
- エラー表示中でも設定変更は原則許可する

## 監視とログ
- MVP では詳細な監視基盤は前提にしない
- 少なくとも API 側で失敗コードとメッセージを返し、クライアントで握りつぶさない
- 開発中はブラウザコンソールとサーバーログで原因追跡できる状態を保つ

## QA 観点
- 不正ファイル選択で画面が壊れない
- 画像読み込み失敗後に再選択できる
- 保存失敗時にプレビューが消えない
- エラーメッセージが次の行動を示している
