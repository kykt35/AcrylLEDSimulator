# Phase 3 Execution Backlog

## 目的
Phase 2 の設計成果物を、Phase 3 の実装順へ変換したバックログとして整理する。

## 実装順の原則
- 画面シェルと状態の土台を先に作る
- 既存 PoC の再利用部分を切り出してから機能を広げる
- 保存は UI と画面遷移の前提が揃ってから実装する

## Backlog

### Epic 1: 画面シェルとルーティング整備

#### Task 1
- `app/page.tsx` をトップ画面責務へ絞る
- `app/simulator/page.tsx` を新設する
- `app/result/page.tsx` を新設する

#### 受入条件
- 3 画面に責務分離されている
- 主要導線で画面遷移できる

### Epic 2: シミュレーター画面コンテナ化

#### Task 2
- `PocWorkbench` を `SimulatorScreen` へ置き換える
- 画像入力、設定、保存、UI 補助 state の持ち場所を整理する
- `SimulatorCanvas` は描画責務へ限定する

#### 受入条件
- 画面状態が 1 箇所に集約されている
- Canvas が props ベースで表示更新できる

### Epic 3: 操作パネル分割

#### Task 3
- 画像設定、発光設定、表示設定、保存設定を分割する
- 状態表示とエラー表示の UI を揃える

#### 受入条件
- パネルが責務ごとに分割されている
- 画像差し替え、LED 色変更、背景切替、カメラ変更、保存が独立して動く

### Epic 4: 保存フロー実装

#### Task 4
- Canvas 書き出し処理を保存フローへ組み込む
- `/api/save` と必要なら `/api/upload` を実装する
- 保存完了モーダルまたは結果画面への遷移を追加する

#### 受入条件
- 現在の見え方を保存できる
- 保存成功 / 失敗の分岐が UI で明確

### Epic 5: 保存結果画面と補助 UI

#### Task 5
- 保存結果画面を実装する
- 注意事項モーダル、保存完了モーダル、共通エラー表示を整備する

#### 受入条件
- 再編集、新規作成、ダウンロード導線が使える
- 注意事項やエラー表示が一貫している

### Epic 6: 仕上げと QA 前準備

#### Task 6
- 既存テストの更新と新規テスト追加
- デスクトップでのレイアウト確認
- Safari / Chrome / Edge を想定した不具合洗い出し

#### 受入条件
- 主要挙動がテストで担保される
- 既知課題が Phase 4 向けに整理される

## 依存関係
- Epic 2 は Epic 1 完了後
- Epic 3 は Epic 2 完了後
- Epic 4 は Epic 2 と Epic 3 の完了後
- Epic 5 は Epic 4 完了後
- Epic 6 は全 Epic の後段で実施

## 実装メモ
- 既存 `LightingControls`、`ImageUploader`、`SimulatorCanvas` は段階的に流用する
- Phase 3 の初回では保存結果画面を簡素にしてもよいが、保存成功の導線だけは確保する
- 比較表示や共有導線は別トピックで扱う
