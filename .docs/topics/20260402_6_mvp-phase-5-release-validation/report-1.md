# Phase 5 Report

- Report Type: milestone-phase-breakdown
- Phase: Phase 5
- Topic: MVP release and validation
- Milestone: M6 MVP公開
- Source Documents: `docs/specs/product/milestones.md`, `docs/specs/product/prd.md`
- Created: 2026-04-02

## Summary

Phase 5 は、MVP を実際に公開し、利用状況とフィードバックから次の改善テーマを決めるフェーズである。リリースそのものを終点にせず、利用計測と改善バックログ整理までをひとまとまりの実施内容として扱う。

## Objective

- 本番環境へ MVP を公開する
- 初期利用データを収集する
- フィードバック導線を整備し、改善要望を蓄積する
- 次フェーズの優先順位付け材料を揃える

## Execution Scope

- 本番デプロイ
- 簡易分析導入
- フィードバック収集導線設置
- 利用状況確認
- 改善要望整理

## Deliverables

- 本番版
- 初期利用レポート
- 次期改善バックログ

## Completion Criteria

- MVP が本番公開され、最低限の運用確認が完了している
- KPI 候補に沿って利用計測を開始している
- ユーザー反応と改善要望が収集できる状態になっている
- M6 の完了として、次の改善テーマに優先順位を付けられる

## Risks And Controls

- 公開後に期待値が過剰に上がる
- 対応: 見え方シミュレーターであることを明記し、実物差異の注意を維持する
- 計測不足で改善判断ができない
- 対応: アップロード完了率、保存利用率、離脱率など最低限の指標を先に決める
- 要望が拡散して優先順位が崩れる
- 対応: 発光表現改善、共有 URL、台座バリエーションなど既存テーマへ束ねて管理する

## Handoff To Next Phase

- 収集した利用データと要望を、発光改善、共有機能、比較表示、注文導線接続などの改善テーマへ整理する
- 次フェーズでは、MVP の成功条件達成度を見ながら、CV 改善に効く機能を優先する
- 公開後の課題は、運用課題と機能改善課題を分けて backlog 化する
