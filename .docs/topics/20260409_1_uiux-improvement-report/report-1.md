# UI使いやすさ分析レポート（現状版）

## メタ情報

- レポート種別: investigation / UX review
- 作成日: 2026-05-04
- 対象: LEDアクスタ シミュレーター MVP
- 確認方法:
  - 実装確認: `components/screens/SimulatorScreen.tsx`, `components/controls/*`, `app/globals.css`
  - 仕様確認: `specs/ux/screens.md`, `specs/ux/user-flow.md`, `specs/product/acceptance-criteria.md`
  - 実画面確認: `http://localhost:3001/`

## 1. 総評

現在のUIは、MVPの中心体験である「PNGを読み込み、3Dプレビューで見え方を確認する」導線は明確に作られている。特に、3Dビュー全体をクリックまたはドラッグ&ドロップ対象にしているため、初回操作の入口は分かりやすい。

一方で、調整から書き出しまでの全体像はタブ内に隠れており、特にモバイル幅では「書き出し」タブが初期表示から欠ける。アップロード後に次に進むべき操作が明示されないため、ユーザーが「画像を入れた後、どの設定を触れば完成なのか」を自分で探す必要がある。

## 2. 良い点

### 2.1 初回操作の入口が明確

画像未選択時、3Dプレビュー領域に「3Dビューへ PNG を追加して始めましょう」と表示される。操作対象が画面中央に大きく出るため、ユーザーは最初に何をすればよいか理解しやすい。

関連実装:
- `components/screens/SimulatorScreen.tsx`
  - `preview-stage`
  - `preview-empty-state`
  - 3Dビュー上のクリック / ドラッグ&ドロップ入力

### 2.2 状態フィードバックがある

画像読み込み、彫刻プレビュー生成、保存処理、エラー表示がそれぞれ状態として管理されている。ユーザーに対して、待機中か、再試行すべきか、成功したかを伝える基盤がある。

関連実装:
- `liveRegionMessage`
- `preview-loading-overlay`
- `ErrorNotice`
- `SaveCompleteModal`

### 2.3 操作分類は自然

操作パネルは「画像」「彫刻」「ライト」「表示」「書き出し」に分かれており、機能分類としては理解しやすい。MVPで必要な調整項目も一通り揃っている。

## 3. 主要な改善点

### 3.1 トップ導線が仕様と実装で逆転している

#### 現状

仕様では、トップ画面はサービス概要を伝え、ユーザーをシミュレーターへ誘導する画面として定義されている。一方、現在の `app/page.tsx` は直接 `SimulatorScreen` を表示している。説明ページは `/about` にあり、ヘッダーの「このアプリについて」から到達する構成になっている。

#### 問題

初見ユーザーは、注意事項や事前準備を読む前にシミュレーター画面へ入る。すぐ試せる利点はあるが、以下が伝わりにくい。

- 透過PNGが推奨であること
- 彫刻用グレースケールの意味
- 実物との差異があること
- 保存までの全体フロー

#### 改善案

優先度高:
- `/` を説明ページ、`/simulator` をシミュレーターに戻す
- または、`/` 直行を維持する場合でも、シミュレーター冒頭に「1. PNG追加 2. 調整 3. 書き出し」の短いステップ表示を追加する

### 3.2 モバイルで書き出し導線が見えにくい

#### 現状

960px以下では1カラムになり、プレビューの下に操作パネルが続く。タブは横スクロールで、「画像」「彫刻」「ライト」「表示」までは見えるが、「書き出し」は右側に隠れやすい。

#### 問題

保存 / ダウンロードは最終目的に近い重要操作だが、ユーザーが横スクロールに気づかないと到達しにくい。実画面確認でも、初期表示ではプレビューが大きく、操作パネル下部までの見通しが弱かった。

#### 改善案

優先度高:
- モバイルではタブを2段グリッドにする
- 画像読み込み後に「次へ: 彫刻調整」「書き出しへ」などのCTAを表示する
- 「書き出し」だけは画像読み込み後に固定フッターまたはパネル上部にも表示する

優先度中:
- 横スクロール継続の場合、右端フェードだけでなく「横にスクロールできます」の視覚的ヒントを初回のみ表示する

### 3.3 未アップロード時にも調整UIが表示される

#### 現状

画像未選択でも、画像サイズ、横位置、縦位置、コンテントフィットの調整UIが表示される。

#### 問題

入力対象がない状態で調整UIが出るため、ユーザーは「この操作は今効くのか」を判断しづらい。特にMVPの初回体験では、選択肢を減らして「まずPNGを入れる」に集中させた方がよい。

#### 改善案

優先度高:
- 画像未選択時は配置調整UIを非表示またはdisabledにする
- 代わりに「PNGを追加すると配置調整ができます」と表示する

優先度中:
- 画像読み込み後に配置調整セクションを開く
- 未選択時はアクリル板サイズだけ触れるようにする

### 3.4 「Contain / Cover / Fill」が一般ユーザーに伝わりにくい

#### 現状

画像配置のコンテントフィット選択肢が英語のまま表示されている。

#### 問題

CSSやデザインツールに慣れていないユーザーには意味が分かりにくい。アクリルスタンドの完成イメージを確認するアプリなので、専門用語より結果が想像できる言葉の方がよい。

#### 改善案

優先度中:
- `Contain` -> `全体を収める`
- `Cover` -> `余白なく広げる`
- `Fill` -> `枠いっぱいに伸ばす`

補足:
- 必要であれば、ボタン下に短い補足文を1行だけ出す
- 用語説明は常時表示ではなく、ヘルプやツールチップでもよい

### 3.5 調整後の次アクションが弱い

#### 現状

タブごとに設定はできるが、完了した後に次のタブへ進む導線はない。タブのステータスラベルはあるが、ユーザーの次アクションを直接案内するものではない。

#### 問題

実際のフローは「画像追加 -> 彫刻調整 -> ライト調整 -> 表示確認 -> 書き出し」だが、UI上は並列タブに見える。ユーザーはどこまで設定すれば保存してよいか判断しづらい。

#### 改善案

優先度高:
- 各タブ末尾に次ステップボタンを置く
  - 画像: `彫刻を調整する`
  - 彫刻: `ライトを調整する`
  - ライト: `表示を確認する`
  - 表示: `書き出しへ進む`
- 画像読み込み後、書き出し可能であることを明示する

優先度中:
- タブに完了アイコンまたは「未設定 / 調整中 / 完了」表示を追加する

## 4. レスポンシブ観点の改善

### 4.1 プレビュー優先は良いが、操作との往復が重い

モバイルではプレビューが先に大きく表示される。これは視覚確認を主役にする方針として妥当だが、調整UIは下に続くため、プレビューを見ながら微調整する体験は弱い。

改善案:
- モバイルでは3Dプレビューをコンパクト表示に切り替える
- 調整中だけプレビューを上部にsticky表示する
- ライト / 表示など即時反映系のタブでは、プレビューへ戻るショートカットを表示する

### 4.2 パネル内スクロールの気づきにくさ

デスクトップでは操作パネルに `max-height: calc(100vh - 220px)` と内部スクロールが設定されている。プレビューを固定的に見ながら操作できる利点はあるが、パネル下部の項目に気づきにくくなる可能性がある。

改善案:
- パネル下端にスクロール可能であることを示すフェードを追加する
- タブ内のサマリーを圧縮し、ファーストビュー内に主要操作を多く入れる
- 最重要操作はタブ下部だけでなく、上部サマリーにも補助表示する

## 5. 表示文言の改善

### 5.1 専門語を結果ベースの言葉に置き換える

対象:
- `コンテントフィット`
- `Contain / Cover / Fill`
- `高さ方向の減衰`
- `しきい値`
- `中間調`

改善方針:
- 初心者向けラベルを主表示にする
- 専門語は補足やtooltipに回す

例:
- `高さ方向の減衰` -> `上方向の光の弱まり`
- `しきい値` -> `彫刻にする明るさの基準`
- `中間調` -> `中間の濃さ`

### 5.2 「全体をリセット」は強い操作に見える

現状、プレビュー上部に「全体をリセット」が常時表示されている。誤操作時に画像や設定が失われる印象があるため、主導線より目立たせすぎない方がよい。

改善案:
- `リセット` をサブメニューや確認付き操作にする
- 画像読み込み後だけ表示する
- 文言を `最初からやり直す` にする

## 6. アクセシビリティ観点

### 6.1 良い点

- タブに `role="tablist"`, `role="tab"`, `role="tabpanel"` が設定されている
- キーボードでタブ移動できる実装がある
- ライブリージョンで状態変化を通知している
- ファイル入力にアクセシブルラベルがある

### 6.2 改善余地

- `role="button"` のプレビュー面の中に、ファイル入力由来のボタンが含まれており、スクリーンリーダー上では構造が少し複雑に見える可能性がある
- `?` ヘルプボタンは `title` 依存で、タッチ端末では内容を確認しづらい
- モーダルのフォーカストラップ、Escキー、復帰フォーカスは継続確認が必要

改善案:
- ヘルプはタップで開く小さな説明ポップオーバーにする
- プレビュー面のクリック可能領域とファイル選択操作の読み上げを整理する
- モーダル操作のキーボードテストをQA観点に追加する

## 7. 優先度付き改善リスト

| 優先度 | 改善項目 | 期待効果 |
|---|---|---|
| 高 | モバイルのタブを2段グリッド化、または次ステップCTAを追加 | 書き出し導線の見落としを減らす |
| 高 | 未アップロード時は配置調整UIを隠す / 無効化する | 初回操作の迷いを減らす |
| 高 | 各タブ末尾に次ステップボタンを追加する | 完了までの流れを明確化する |
| 高 | `/` と `/about` の役割を見直す | 初見ユーザーへの説明不足を減らす |
| 中 | `Contain / Cover / Fill` を日本語化する | 設定結果を想像しやすくする |
| 中 | パネル内スクロールの視覚ヒントを追加する | 下部項目の見落としを減らす |
| 中 | 専門語を初心者向けラベルに置き換える | 操作理解を高める |
| 低 | `?` ヘルプをタッチ対応ポップオーバーにする | 補足情報へのアクセスを改善する |

## 8. 推奨する次の実装順

1. 画像未選択時のUI整理
   - 配置調整UIを非表示またはdisabledにする
   - 画像追加の案内を主役にする

2. モバイル操作パネルの改善
   - タブを2段表示にする
   - 「書き出し」を初期視界から隠れない位置に置く

3. ステップ導線の追加
   - 各タブ末尾に次ステップCTAを追加する
   - 画像読み込み後に「書き出し可能」状態を明示する

4. 文言の改善
   - `Contain / Cover / Fill` を日本語化
   - 彫刻・発光系の専門語に補足を追加

5. 入口設計の見直し
   - `/` を説明ページに戻すか、シミュレーター直行のまま短い開始ガイドを追加する

## 9. 結論

現在のUIは、MVPとして必要な機能と状態表示は揃っている。大きな問題は機能不足ではなく、操作順序と最終アクションの見通しである。

最初に直すべきは、モバイル時のタブ視認性、未アップロード時の不要な操作表示、タブ間の次ステップ導線である。この3点を改善すると、ユーザーは「PNGを入れる」「必要な調整をする」「書き出す」という主導線をより迷わず完了できる。
